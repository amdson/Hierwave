# Luanti plan: infinite tile worlds in real time (2026-10-12)

Goal: walk around an infinite world generated by `castlegen/infinite.py`,
first in a 2D viewer, then in Luanti with each tile built from blocks.
Tiles stay on a 2D grid; the third dimension comes from fixed per-tile
templates.

## 0. Contract (every thread works to this)

### Tile sets and sampler settings
Two tile sets, exported once from Python (thread A) and fixed afterwards:
- `biomes`: `castlegen.infinite.biomes()` (T = 8, pair tables),
  `Schedule.anneal(S=64)`.
- `city`: `castlegen.citytiles` (T = 3907, SocketModel, wildcard id T) with
  weights BOUNDARY_W = 0.5, ZONE_W = {P 0.4, R 1.0, C 1.0, D 1.0, I 1.0,
  W 0.8, A 0.6}, FEAT_W unchanged, u = -log w, wild_u = 20,
  `Schedule.anneal(S=64, beta0=1.0, gamma0=2.0)` (~0.6% wildcards).
  City speed work (score only socket-compatible tiles) is A's last item.

### Sampler API (C, thread A)
`castlegen/csrc/hwsampler.c` -> `cache/libhwsampler.dylib`, plain C, no
threads inside; callers may call from several threads (the world cache is
mutex-protected).
```
hw_model* hw_model_load(const char* path);        /* file written by Python export */
void      hw_model_free(hw_model*);
int       hw_model_T(const hw_model*);           /* tiles; wildcard id == T if enabled */
int       hw_tiles(const hw_model*, uint64_t seed, int64_t y0, int64_t x0,
                   int H, int W, int32_t* out);   /* exact, row-major (H, W) */
hw_world* hw_world_new(const hw_model*, uint64_t seed, int C);   /* chunk cache, C x C */
int       hw_world_region(hw_world*, int64_t y0, int64_t x0, int H, int W, int32_t* out);
void      hw_world_free(hw_world*);
```
Output must equal `castlegen.infinite.generate` bit for bit (same hash,
same draws).  Python wrapper: `castlegen/hwsampler.py` (ctypes).
Model files: `luanti/games/hierwave/mods/hierwave_gen/data/{biomes,city}.hwm`.

### Coordinates
- Tile (row r, col c), r grows southward, c eastward.
- Footprint N = 8 blocks per tile side.  Template cell (i, j): i = row
  north -> south, j = column west -> east, 0..7.
- Luanti: world x = 8 c + j, world z = -(8 r + i)  (+z is north).
- Template layer k = 0..23 is world y = k - 4.  Layers 0-3 are ground
  (top solid block of flat land at layer 3, world y = -1; you walk at y = 0).
  Below layer 0 the mod fills stone; above layer 23 is air.
- Water surface: top water block at layer 2 (one below land, so shores
  read).  Highway deck: layer 8.

### Palette (ids are line numbers of `luanti/palette.txt`, 0 = air)
```
0 air         1 stone       2 dirt        3 grass       4 sand
5 water       6 gravel      7 snow        8 asphalt     9 road_line
10 concrete   11 paving     12 curb       13 rail       14 ballast
15 fence      16 tarmac     17 runway_mark 18 deck      19 pillar
20 trunk      21 leaves     22 hedge      23 house_wall 24 house_roof
25 shop_wall  26 glass      27 tower_wall 28 tower_top  29 shed_wall
30 shed_roof  31 chimney    32 tank       33 plaza      34 fountain
35 lamp       36 rock       37 deep_water 38 dark_grass 39 window
```
Luanti node names: `hierwave:<name>`, flat coloured cubes (water and
deep_water liquid-looking, glass and leaves see-through).  Thread D owns
the node definitions; everyone else uses the names.

### Template file (thread C writes, D/E read)
`luanti/games/hierwave/mods/hierwave_gen/data/{biomes,city}.hwt`, little endian:
```
char[4] "HWT1"; uint32 n_templates; uint32 N (8); uint32 L (24);
uint8 data[n_templates][L][N][N]      /* [t][k][i][j], palette ids */
```
For `city` n_templates = T + 1 (last = wildcard).  Python reader and writer
in `castlegen/prefabs.py`.

### Prefab text format (thread C)
Files in `castlegen/prefabs/{city,biomes}/*.txt`:
```
name: zone_R
size: 4 4            # rows (i) cols (j)
legend: g=grass w=house_wall r=house_roof d=dirt .=air _=keep
layer 0-2: d         # a whole layer (or range) of one char
layer 3:
gggg
gwwg
...
layer 4:
...
```
Layers not listed are `_` (keep: do not overwrite).  `.` writes air.
Rows are i (north first), columns j (west first).

City pieces (drawn once in the stated orientation; the assembler mirrors
or rotates):
- `zone_<Z>.txt`, Z in P R C D I W A: the NW quadrant, 4x4, i, j = 0..3.
  Its inner sides (row 3 = toward the tile centre southward, column 3 =
  eastward) may be covered by a road strip; keep the building inside rows
  0-2, columns 0-2, and draw the margin as yard / sidewalk.  The assembler
  mirrors it to NE (flip j), SW (flip i), SE (both).  Airport labels H.. and
  V.. all use `zone_A`.
- `edge_<f>.txt`, f in street avenue rail highway: the N half-edge strip,
  size 4 x 2 at rows 0-3, columns 3-4 of the tile (it reaches the centre;
  the S strip, rows 4-7, is it rotated 180 degrees, E and W are it rotated
  90 degrees).  `bridge_<f>.txt`: the same strip when both corners of the
  edge are water.
- `wildcard.txt`: a full 8x8 tile (a plaza).
Assembly: four quadrants, then strips in priority street < avenue < rail <
highway (later overwrites), then the centre 2x2 (rows 3-4, cols 3-4) takes
the highest-priority feature present.

Biome pieces: `band_<name>.txt`, full 8x8 tiles, one per band (deep water
sand grass forest hill rock snow): surface height rising with the band
(adjacent bands differ by at most one band, so at most ~3 layers).
