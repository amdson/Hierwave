# Hierwave

Fixed-budget hierarchical sampling of tile worlds: coarse levels that are
learned, fine levels that are designed, every level sampled locally in a
fixed number of sweeps so that infinite worlds can be generated chunk by
chunk.  The goals are in `notes/constitution.md`.

## Where things are

| | |
|---|---|
| `castlegen/channels/` | **The current implementation.**  Channels, factors, certificates, per-channel samplers, the bootstrap trainer, and the toy models that validate them. |
| `castlegen/bitgibbs.py`, `castlegen/csrc/` | The bit-sliced tile sampler in C: the planned fast backend for the tile level, not yet behind the channel interface. |
| `castlegen/legacy/` | Earlier generations (JAX castles, promises and texture synthesis, the generic joint sampler, macro objects, block connectivity).  Runnable, not developed.  Its docstring says which notes describe each. |

| `images/` | Figures and renders written by the experiments; gitignored, regenerated by the scripts. |

## The current design in one paragraph

A world is a stack of levels, coarsest first.  Each level is a set of
channels (grids of values with declared views) tied by designed local
factors: pair and count tables, unary terms, painted channels, and
certificates for constraints like connectivity.  Coarser channels write
into finer ones; a finer level never reads a coarser level's internals
except through those writes.  The bidirectional model `p*` is the
specification.  What is sampled is a forward chain: each level draws from
its designed energy plus a learned potential that stands in for the free
energy of everything below it.  That potential is a sum of local terms
over candidate values, with its support (what the children's hard writes
forbid) computed from the writes and its finite part fitted.  Training
is a bootstrap: contexts from the forward chain, local targets from `p*`
computed by annealed importance sampling over one site's window, a
Rao-Blackwellised cross-entropy fit, level by level from the tiles up.
`notes/dsl_updates.md` has the decisions and what the build measured;
`notes/dsl_interface.md` the programmatic shape; `notes/reference_math.tex`
the mathematics.

## Running

```
uv sync                                   # or: pip install -e .[dev]
NUMBA_NUM_THREADS=1 python -m pytest tests/channels -q
NUMBA_NUM_THREADS=1 python notes/experiments/circles_biome_fit.py       # the main validation run
```

Experiments are single core by design (`NUMBA_NUM_THREADS=1`); each run
reports into `images/` and its numbers are recorded in the test note it
belongs to.

## Reading order

1. `notes/constitution.md`: what counts as correct.
2. `notes/dsl_updates.md`: the committed design, C1 to C5, with results.

6. The test notes that led here: `potts_test.md`, `circles_test.md`,
